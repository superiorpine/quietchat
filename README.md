# QuietChat для iPhone

Готовое веб-приложение, которое устанавливается на главный экран из Safari.
Вы шифруете сообщения на телефоне, пересылаете шифротекст через Telegram,
а друг расшифровывает его у себя. Публичные ключи сохраняются после первого обмена.

Для личного использования подходит бесплатный GitHub Pages с публичным репозиторием.
Apple Developer, App Store, платный сервер и покупка домена не нужны.
Сборка и установка Python, Node.js или npm для публикации тоже не нужны.

## 1. Загрузить на GitHub с компьютера — самый простой способ

1. Скачайте и распакуйте **QuietChat-iPhone.zip**. Откройте папку `QuietChat-iPhone`.
2. Войдите в https://github.com/. Если аккаунта нет, создайте бесплатный.
3. Откройте https://github.com/new.
4. В поле **Repository name** напишите `quietchat`. Выберите **Public**.
   Включите **Add README**, чтобы появилась ветка `main`, и нажмите **Create repository**.
5. В созданном репозитории откройте **Add file → Upload files**.
6. Перетащите **содержимое** распакованной папки: файлы и папки `vendor`, `icons`, `tests`.
   Не загружайте сам ZIP и не перетаскивайте целиком внешнюю папку `QuietChat-iPhone`.
   Файл `index.html` должен находиться сразу в корне репозитория.
7. Загрузите README из архива вместо начального README. Внизу страницы сохраните изменения
   в `main` кнопкой **Commit changes**. Если GitHub предлагает **Propose changes**,
   закончите создание и объединение Pull Request, чтобы файлы попали в `main`.
8. Если скрытый файл `.nojekyll` не загрузился, создайте его отдельно:
   **Add file → Create new file**, имя `.nojekyll`, содержимое `QuietChat static files`,
   сохраните в `main`. Так GitHub просто опубликует готовые файлы без обработки Jekyll.
9. Перейдите в **Settings → Pages**. В **Build and deployment** выберите:
   **Source: Deploy from a branch**, **Branch: main**, **Folder: /(root)**. Нажмите **Save**.
10. Дождитесь завершения публикации. Она может занять до 10 минут.
    Адрес появится в **Settings → Pages → Visit site**.

Обычный адрес сайта будет таким:

`https://ВАШ_ЛОГИН.github.io/quietchat/`

Замените `ВАШ_ЛОГИН` на свой логин GitHub. Для другого имени репозитория изменится
последняя часть адреса. HTTPS обязателен. Если доступна настройка **Enforce HTTPS**,
оставьте её включённой.

В корне должны быть `index.html`, `styles.css`, `app.js`, `crypto-core.js`,
`crypto-worker.js`, `sw.js`, `manifest.webmanifest`, `.nojekyll` и `README.md`.
В `vendor` — оба файла JavaScript и лицензии, в `icons` — три файла PNG.
Папка `tests` содержит проверки для разработчика и не нужна для обычного запуска.

**В репозиторий загружаются только файлы программы из этого архива.**
Пароли, личные ключи, ваши файлы `.qcbkp` и `.qcvault` туда не загружайте.
Открытый исходный код не содержит пользовательских ключей.

## 2. Если есть только iPhone

Можно сделать ту же публикацию через Safari на github.com. Загрузка папок с телефона
менее удобна, поэтому файлы загружаются в несколько приёмов.

1. Сохраните ZIP в приложение **«Файлы»**. Нажмите на ZIP — появится распакованная папка.
2. В Safari создайте публичный репозиторий `quietchat` по шагам выше.
   Если нужных кнопок не видно, в меню Safari выберите **«Запросить настольный веб-сайт»**.
3. Через **Add file → Upload files → choose your files** выберите основные файлы
   из распакованной папки: `index.html`, `styles.css`, `app.js`, `crypto-core.js`,
   `crypto-worker.js`, `sw.js`, `manifest.webmanifest`, `README.md`.
   Сохраните их в `main`. При необходимости загружайте по одному.
4. Создайте папку для библиотеки: **Add file → Create new file**, имя
   `vendor/README.txt`, содержимое `Local libsodium library`, сохраните в `main`.
   Откройте появившуюся папку `vendor`, нажмите **Add file → Upload files** и загрузите
   `libsodium-sumo.js`, `libsodium-wrappers.js`, оба файла `*-LICENSE.txt` и `versions.json`
   из папки `vendor` в архиве. Лицензии нужно сохранить вместе с библиотекой.
5. Аналогично создайте `icons/README.txt`, откройте папку `icons` и загрузите
   `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` из архива.
6. Создайте `.nojekyll` в корне и включите **Settings → Pages → Deploy from a branch → main → /(root)**.
7. Откройте выданный адрес сайта. В репозитории файлы библиотеки должны лежать
   именно в `vendor`, а изображения — именно в `icons`.

Не нужно создавать приложение на Python или загружать ZIP как один файл.
GitHub Pages раздаёт HTML, CSS и JavaScript; распаковки ZIP на сервере не происходит.

## 3. Установить на iPhone

Рекомендуемая платформа — iPhone с **iOS 17 или новее**, обычный Safari.

1. Откройте опубликованный HTTPS-адрес **в Safari**, а не во встроенном браузере Telegram.
2. Откройте меню Safari **«Поделиться»** и выберите **«На экран “Домой”»**.
   В новых версиях iOS при наличии переключателя включите **«Открывать как веб-приложение»**.
   Если пункта нет, найдите его через редактирование действий меню.
3. Нажмите **«Добавить»**. На главном экране появится иконка QuietChat.
4. Запустите приложение с этой иконки **при включённом интернете**.
5. Создайте свой пароль из 12 или более символов, лучше длинную случайную фразу.
6. Во вкладке **«Профиль»** дождитесь строки **«Приложение сохранено для работы без интернета»**.
7. Там же нажмите **«Сохранить резервную копию»**, выберите **«Сохранить в Файлы»**
   либо сохраните скачанный файл. Проверьте, что файл `.qcbkp` действительно появился.

Создавайте профиль после запуска с иконки. Safari и приложение на главном экране
могут использовать разные хранилища. Если профиль уже создан в Safari, сохраните
его копию, а при первом запуске с иконки выберите **«У меня есть резервная копия»**.

Для проверки автономной работы: закройте профиль, включите авиарежим, снова откройте
приложение с иконки и войдите с паролем. Шифрование должно работать; для Telegram
интернет, конечно, потребуется. Браузер может удалить сохранённые данные, поэтому
автономный кэш не заменяет резервную копию ключа.

## 4. Обменяться ключами — один раз

1. Друг устанавливает приложение по **той же ссылке**, но создаёт **свой отдельный профиль**.
2. Оба открывают **«Мой ключ»** и копируют строку `QCK1:…`. Отправьте эти строки друг другу.
3. Во вкладке **«Друзья»** нажмите **«Добавить»**, введите имя и вставьте публичный ключ друга.
4. Созвонитесь или встретьтесь. Друг читает свой отпечаток из **«Мой ключ»**,
   а вы сравниваете его с отпечатком в окне добавления. Сравните все 16 групп.
   Затем поменяйтесь ролями.
5. Отметьте **«Я сверил(а) весь отпечаток с другом»** и сохраните контакт.
   До проверки можно сохранить контакт, но обмен сообщениями с ним будет отключён.

Проверочная часть строки обнаруживает ошибку копирования. Она **не доказывает**,
что ключ принадлежит другу. Отпечаток сравнивается по независимому каналу:
его пересылка рядом с ключом в том же чате не защищает от подмены.
Пароль и резервную копию другу не отправляют.

## 5. Переписываться через Telegram

**Отправить:** «Отправить» → выберите друга → напишите текст → «Зашифровать».
Далее нажмите **«Поделиться»** и выберите Telegram и нужный чат.
Если Telegram не показывается, нажмите **«Копировать»**, откройте Telegram и вставьте строку.
Получатель в Telegram выбирается вами: приложение не проверяет, кому вы пересылаете строку.
Расшифровать её сможет обладатель приватного ключа выбранного в QuietChat друга.

**Прочитать:** скопируйте строку из Telegram → QuietChat → «Прочитать» → вставьте
в верхнее поле. Через короткую паузу сообщение расшифруется автоматически.
Есть и кнопка **«Расшифровать»**. Ключ отправителя определяется по сохранённому контакту.

**Копирование и вставка:** сообщения, ключи и отпечатки можно выделять обычным
удержанием пальца. Кнопки работают через системный буфер обмена. Если iOS спрашивает
разрешение на вставку, разрешите её. При отказе удерживайте палец внутри поля
и выберите **«Вставить»**. Поля с готовым шифротекстом и прочитанным сообщением
доступны для выделения и копирования; ввод находится в отдельных полях.

Для длинного сообщения используйте **«Сохранить сообщение в файл»** и перешлите `.qcm`.
Друг открывает его через **«Открыть файл»**. Ограничение исходного сообщения — 64 КиБ UTF-8.
Приложение шифрует текст, но не фотографии и другие вложения.

## 6. Сохранение, закрытие и восстановление

- В браузерном хранилище лежит **только зашифрованный профиль**: приватный ключ,
  контакты и идентификаторы последних 10 000 прочитанных сообщений.
  Текст переписки в историю не записывается.
- **«Закрыть»** убирает открытые тексты и завершает процесс, в котором находились ключи.
  Повторный доступ требует пароля. Автоматическое закрытие — после 5 минут без действий
  или примерно 1 минуты в фоне; после возвращения из фона срок проверяется снова.
- Браузер и JavaScript не гарантируют стирание каждой копии секрета из памяти.
  Скопированный вами текст остаётся в системном буфере до его замены.
- Пароль нельзя сбросить. Потеря профиля/копии или пароля может навсегда закрыть
  доступ к старым сообщениям.
- Смена пароля сохраняет ключи. После неё сделайте новую копию: старые копии требуют старый пароль.
- На новом iPhone установите приложение и до создания нового профиля нажмите
  **«У меня есть резервная копия»**. Выберите `.qcbkp` и введите пароль этой копии.
- Восстановление поверх существующего профиля отключено, чтобы случайно не потерять ключ.
  Если нужно заменить профиль, сначала сохраните его копию; очистка данных сайта
  средствами iOS удаляет локальный профиль.
- Используйте один открытый экземпляр для изменений контактов и пароля.
  При конфликте с другим окном программа закроет профиль и предложит открыть его снова.
- Не переименовывайте репозиторий без копии профиля: адрес приложения и область
  его хранилища изменятся. Через копию можно перенести профиль на новый адрес.

## 7. Совместимость с прежним QuietChat на Python

Поддерживаются те же карточки **QCK1**, сообщения **QC1** и зашифрованные профили версии 1.
Можно переписываться между iPhone и компьютерной версией.
Для переноса своего профиля с компьютера создайте `.qcbkp` в Python-программе
и восстановите его на iPhone. Переносить копию своего ключа нужно лично себе, а не другу.
Изменения контактов, пароля и отметок прочтения между устройствами автоматически не синхронизируются.
Можно также использовать на телефоне новый отдельный ключ и добавить его как отдельный контакт.

## 8. Что реализовано и чего не обещает эта версия

Сообщения: **libsodium crypto_box**, X25519 + XSalsa20-Poly1305, случайный 24-байтный nonce.
Профиль: **Argon2id** (3 прохода, 64 МиБ памяти, новая случайная соль) + **SecretBox**.
В заголовке передаются идентификаторы ключей; внутри защищённого сообщения
повторно проверяются отправитель и получатель. Отметка повтора не запрещает перечитать сообщение.

Библиотека libsodium.js **0.8.4** включена в `vendor`; загрузки криптографии со стороннего CDN нет.
Шифрование и обработка пароля выполняются в отдельном Worker на устройстве.
GitHub Pages используется для выдачи программы. Код не содержит API отправки
профилей, паролей или сообщений серверу, аналитики и бота Telegram.
Запросы файлов сайта и проверка обновлений остаются видимыми хостингу.

Это самостоятельно собранное приложение **без независимого аудита**.
Нет Double Ratchet и прямой секретности: если приватный ключ украден,
ранее перехваченные сообщения этой пары могут быть раскрыты.
Обновлённый или подменённый веб-код имеет доступ к данным при открытии профиля,
поэтому нужно доверять владельцу сайта, его GitHub-аккаунту и обновлениям.
HTTPS не решает проблему вредоносного кода от самого сайта.
Telegram получает шифротекст, но сохраняет сведения об участниках, времени и размере сообщений.
Копирование открытого текста, скриншоты и заражённый телефон находятся вне защиты шифрования.
Проверка Box не является электронной подписью для доказательства авторства третьим лицам.

## 9. Обновления и разработка

Чтобы выпустить новую версию, загрузите изменённые файлы в `main`.
При изменении файлов программы увеличьте строку версии кэша в `sw.js`, чтобы
телефон загрузил полный новый комплект. После публикации: «Профиль» →
«Проверить обновление» → «Закрыть профиль и обновить».
Профиль хранится отдельно от файлов сайта и сохраняется при обычном обновлении.
Сделайте резервную копию перед значительными изменениями программы.

Проверка криптографического ядра для разработчика с Node.js 20+:

```sh
node tests/test-crypto.cjs
```

Проверка реального браузерного интерфейса через Playwright/WebKit:

```sh
npm install --no-save playwright
npx playwright install --with-deps webkit
node tests/test-browser.cjs
```

Это команды для компьютера разработчика, а не для установки на iPhone.
Тесты используют временные профили; установку с главного экрана и настоящее меню
Telegram необходимо дополнительно проверить на вашем iPhone.

В этой сборке проверены криптографические операции, отказ при повреждённом сообщении,
проверка ключей, пароли и восстановление; обмен сообщениями и профилями между
JavaScript и Python/PyNaCl в обе стороны. В настоящем WebKit с размером iPhone
проверены создание профиля, контакты, чтение, файлы, резервная копия, смена пароля,
закрытие, повторная загрузка и шифрование при недоступном сервере, ширины 320–1024 px.
В браузерном тесте вызовы системного буфера и меню отправки заменены тестовыми:
поведение разрешений iOS и выбор Telegram проверяются на устройстве.

## 10. Если что-то не получилось

| Что видно | Что сделать |
|---|---|
| 404 вместо сайта | Дождитесь публикации в Pages. Проверьте `main`, `/(root)` и `index.html` в корне. |
| Показывается README | `index.html` загружен во вложенную папку. Перенесите содержимое в корень. |
| Не загружается шифрование | Проверьте `vendor/libsodium-sumo.js`, `vendor/libsodium-wrappers.js` и `crypto-worker.js`. |
| Не вставляется текст | Удерживайте палец в поле → «Вставить»; разрешите запрос iOS. |
| Нет Telegram в меню | Скопируйте шифротекст и вставьте в Telegram вручную. |
| Нельзя зашифровать | Сохраните контакт и отметьте проверку отпечатка после сверки. |
| Сообщение предназначено другому ключу | Друг выбрал другой ваш профиль. Сравните текущий публичный ключ. |
| Неверный пароль | Нужен пароль профиля или пароль, действовавший на момент создания копии. |
| Без сети белый экран | Сначала запустите с иконки при интернете и дождитесь готовности кэша. |
